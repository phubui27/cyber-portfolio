# Week 1 – SOC Fundamentals Summary

## Overview
Week 1 focuses on building a solid foundation for a junior SOC analyst role.  
The goal is not to learn tools or hacking techniques, but to understand **how SOC thinks, observes, and responds to security events**.

---

## 1. Cyber Security in an organization

Cyber Security in a company can be divided into four main functions:

- **Prevention**
  - Prevent attacks through technical controls and policies (firewalls, hardening, access control)

- **Detection**
  - Monitor logs and traffic to identify abnormal behavior

- **Response**
  - Investigate and handle confirmed security incidents

- **Improvement**
  - Learn from incidents to improve detection rules and defenses

### Where SOC fits
- SOC primarily operates in **Detection** and **Response**
- SOC analysts monitor alerts, analyze logs, and investigate suspicious activities daily

---

## 2. SOC role and daily activities

A typical SOC analyst day includes:
- Reviewing alerts generated by SIEM
- Performing triage to filter false positives
- Investigating suspicious logs and traffic
- Escalating confirmed incidents
- Documenting findings and actions in reports

SOC analysts focus on **pattern recognition**, not single events.

---

## 3. Network fundamentals for SOC

Key network concepts learned:
- **IP address**: identifies a device on the network; SOC uses it to trace attack sources
- **LAN vs Public IP**: internal traffic vs outbound traffic
- **ICMP (Ping)**: used to check host availability
- **Common ports**:
  - Port 22 (SSH): brute force risk
  - Port 53 (DNS): domain investigation
  - Port 443 (HTTPS): web traffic analysis
- **src_ip / dst_ip**:
  - src_ip: source (sender)
  - dst_ip: destination (receiver)

SOC insight:
- Unusual outbound connections or uncommon ports are often suspicious

---

## 4. Web & HTTP fundamentals (SOC perspective)

Core HTTP concepts:
- HTTP is an application-layer protocol based on request/response
- SOC analyzes HTTP through logs, not the web interface

Key elements SOC focuses on:
- **Method** (GET, POST)
- **URL / Path**
- **Status code**

### Important methods
- **GET**: retrieve data (page load, link click)
- **POST**: send data (login, form submission)

### Important status codes
- 200: successful request
- 301: redirect
- 401: unauthorized (authentication failure)
- 403: forbidden (permission issue)
- 404: resource not found (possible scanning)
- 500: server error (possible exploit or misconfiguration)

SOC insight:
- One request means little; **repeated patterns** indicate threats

---

## 5. Linux fundamentals for SOC

Linux is a core environment for SOC log analysis.

Key commands learned:
- `pwd`, `ls`, `cd`: navigate the filesystem
- `cat`: view log content
- `tail`: view latest events
- `grep`: filter suspicious patterns

SOC mindset:
- SOC does not read logs line by line
- SOC filters logs by IP, method, status code, and keywords
- `grep` is the most important command for SOC log analysis

---

## 6. Windows Event Logs (SOC foundation)

Windows logs are critical because most enterprise environments run Windows.

### Windows Event Log types:
- Application
- System
- **Security** (most important for SOC)

### Core Event IDs learned:
- **4624**: successful logon
- **4625**: failed logon
- **4634**: logoff
- **4672**: special privileges assigned (admin login)

SOC insight:
- Repeated Event ID 4625 indicates possible brute force
- Successful admin logins require close monitoring
- SOC correlates Event IDs over time to detect incidents

---

## 7. SOC alert and incident workflow

### Alert vs Incident
- **Alert**: a warning generated by SIEM based on rules
- **Incident**: a confirmed security event with real impact

Most alerts are **not incidents**.

### SOC Tier 1 workflow:
1. Receive alert
2. Triage (most important step)
3. Initial investigation
4. Decide: close, monitor, or escalate
5. Document actions and findings

SOC Tier 1 focuses on:
- Alert review
- Pattern identification
- Clear documentation
- Proper escalation

---

## 8. Key SOC mindset developed in Week 1

- SOC observes behavior, not tools
- SOC looks for patterns, not single events
- Logs tell stories when correlated correctly
- Documentation is as important as investigation

---

## 9. Key takeaway

Week 1 establishes the foundational SOC mindset:
- Understanding where SOC fits in an organization
- Reading network, web, Linux, and Windows logs
- Differentiating alerts from incidents
- Following a structured SOC workflow

This foundation prepares for deeper detection, correlation, and investigation in the following weeks.
